# Sources and reuse decisions

Accessed 2026-09-25. These references explain the provenance and limits of the exploratory model. A citation is not a claim that this app reproduces a source's complete method or has been validated against its results. Numerical constants actually used by the app are listed in the parameter reference and code.

| ID | Source and section read | Applicability and decision |
| --- | --- | --- |
| S1 | [NIST Chemistry WebBook, carbon dioxide, “Phase change data”](https://webbook.nist.gov/cgi/cbook.cgi?ID=C124389&Mask=4) | Reference for CO₂ phase constraints and sublimation energy. The page reports a triple point at 216.58 K and 5.185 bar, and a sublimation enthalpy of 25.2 kJ/mol at 195 K (about 573 kJ/kg). The solver uses a rounded 571 kJ/kg approximation near its 194.65 K source set temperature; this is not a temperature-dependent property fit. Do not apply a solid-to-gas-only model if the state enters a liquid-capable or high-pressure regime. NIST's database content is copyrighted; no tables or plots are copied into the app. |
| S2 | [MOOSE PorousFlow, “Fluid flow,” “Flux,” and “Heat flow”](https://mooseframework.inl.gov/modules/porous_flow/governing_equations.html) | Governing-equation reference for conserved species inventory, advective and diffusive flux, Darcy flow, pressure/temperature dependencies, and heat balance. PorousFlow itself is **not** embedded. This reference shows what the reduced app omits, particularly full multiphase coupling and solid mechanics. |
| S3 | [Three.js documentation and examples](https://threejs.org/docs/) | Browser 3D rendering and camera controls only. Three.js is not a porous-flow solver. Its [MIT license](https://github.com/mrdoob/three.js/blob/dev/LICENSE) applies to the library. |
| S4 | [Rapier documentation, “About Rapier”](https://rapier.rs/docs/) | Candidate for illustrative rigid-body movement only. Its documentation identifies an Apache-2.0 license and describes real-time rigid bodies, collisions, and JavaScript bindings. It is not geomechanics or a rupture model. Include it only if the code actually imports it. |
| S5 | [NIST FiPy documentation, introduction](https://pages.nist.gov/fipy/en/stable/) | Reference for a possible future finite-volume PDE solver, including transient diffusion/convection/source terms. FiPy is not required for this TypeScript release and is not embedded unless it appears in the dependency manifest. |
| S6 | Huang and Rein (2017), [“Downward spread of smouldering peat fire: the role of moisture, density and oxygen supply,” abstract, experiments, and footnote A](https://doi.org/10.1071/WF16198) | Experimental context and a warning against a universal monotonic moisture multiplier. Their reported 30 cm peat-column spread depended on oxygen supply and dry bulk density; in their tested range, downward spread increased with moisture content. Their moisture content is water mass divided by dry soil mass, not pore-water saturation. The app does **not** claim to reproduce their apparatus, kinetics, or rates. No article text, figure, or data table is copied. |
| S7 | [OpenAI Codex prompting guide](https://developers.openai.com/codex/prompting) | Build-process reference only; no scientific equation or property is taken from it. |
| S8 | Bennett (1976), [USGS *Introduction to Ground-Water Hydraulics*, Part II, “Darcy's law”](https://pubs.usgs.gov/twri/twri3-b2/pdf/twri_3-B2_b.pdf); [publication record](https://pubs.usgs.gov/publication/twri03B2) | The USGS-indexed Part II passage defines pressure as force per area in a pore-fluid element and distinguishes intrinsic permeability (m²) from hydraulic conductivity. This supports terminology and units for the reduced slow-flow calculation; it does **not** validate a pressure-area display proxy as soil force, blast load, or failure prediction. The PDF endpoint returned HTTP 403 during this review; no additional equations or property values are claimed from unread pages. |
| S9 | Remson and Randolph (1962), [USGS *Review of Some Elements of Soil-Moisture Theory*, publication record](https://pubs.usgs.gov/publication/pp411D) | The report was supplied as an additional official reference. Its metadata were inspected, but its PDF endpoint returned HTTP 403 and its content was not used for this release's model or a quantitative moisture law. |
| S10 | Neuzil (2003), [USGS record and abstract for “Hydromechanical coupling in geologic processes”](https://pubs.usgs.gov/publication/70026090) | Conceptual limit for any soil-response display. The abstract describes effective stress as total stress minus fluid pressure and explains that coupled force balance, fluid mass conservation, rheology, material geometry, and boundaries matter for deformation/failure. It does not calibrate this app's soil-event coefficients or validate predicted fracture, displacement, or blast forces. Only the abstract and record were reviewed. |
| S11 | [Electron security guide](https://www.electronjs.org/docs/latest/tutorial/security), [application packaging guide](https://www.electronjs.org/docs/latest/tutorial/tutorial-packaging), and [Electron Packager](https://electron.github.io/packager/main/) | Desktop packaging and renderer-isolation guidance only. The macOS app bundles its built interface in Electron, serves static files through loopback, and keeps Node APIs out of the renderer. These sources do not validate the simulator's physics. Electron is MIT licensed; bundled Chromium notices are retained in the app. |

## Application libraries

The pinned package manifest and lockfile identify exact installed versions. React supplies interface state and controls; [React Three Fiber](https://github.com/pmndrs/react-three-fiber) and [Drei](https://github.com/pmndrs/drei) connect the React interface to Three.js; [Recharts](https://github.com/recharts/recharts) plots histories; [Lucide](https://github.com/lucide-icons/lucide) supplies icons. These libraries do not provide scientific validation. The installed manifests declare MIT for React, React DOM, Three.js, React Three Fiber, Drei, and Recharts, and ISC for Lucide. Lucide's license file also identifies Feather-derived icons under MIT. Direct dependency license texts appear in `THIRD_PARTY_NOTICES.md`.

[Vite](https://vite.dev/guide/) builds the interface and serves source-development previews; [Vitest](https://vitest.dev/guide/) runs unit tests. Official [Vite 7 runtime guidance](https://vite.dev/blog/announcing-vite7) and the [Vitest 5 migration guide](https://vitest.dev/guide/migration/) together support documenting Node.js 22.12+ for the source build. The packaged macOS app includes its own Electron runtime and needs no separate Node installation. These are packaging and development tools, not runtime physics dependencies.

## Reuse boundary

The implementation favors a local TypeScript app with a small inspectable solver. Three.js is appropriate for visualization. Electron gives the built interface a dedicated Mac window without changing its solver. MOOSE PorousFlow and FiPy provide directions for later solver work, but embedding either in this release would add substantial setup without making an uncalibrated peat scenario predictive. Rapier is useful only if the illustration needs rigid-body collisions; movement remains artistic even with a physics engine.
